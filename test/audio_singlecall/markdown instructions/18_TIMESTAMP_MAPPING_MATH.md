# 📐 The Math of the Kairos Audio Pipeline
### How We Chunk, Transcribe, and Re-Map Audio to PySceneDetect Timestamps

This document explains the exact calculations and flow used in `whisper_singlecall.py` and `ast_parallel.py` to ensure that audio perfectly aligns with the original visual scenes.

---

## Part 1: Whisper Transcription

Whisper is designed to transcribe continuous speech. Passing it tiny 2-second scenes individually destroys its context window and dramatically increases API latency. Instead, we chunk the continuous audio mathematically.

### 1. Dynamic Chunking Formula
In `whisper_singlecall.py`, we take the entire audio timeline and slice it into 600-second (10-minute) blocks with a 30-second overlap to prevent words from being cut in half.

**The Formula (`transcribe_parallel`):**
```python
chunk_size_sec = 600
overlap_sec = 30
duration = len(audio) / sr  # e.g., 8565 seconds (142 mins)

start = 0
while start < duration:
    end = min(start + chunk_size_sec + overlap_sec, duration)
    # Slice the waveform array:
    chunk_samples = audio[int(start * sr) : int(end * sr)] 
    
    # Send to worker (parallel API call)
    chunks_args.append((chunk_samples, start))
    
    start += chunk_size_sec
```
*Example for a 20-minute video:*
- Chunk 1: `00:00` to `10:30` (Start: 0s, End: 630s)
- Chunk 2: `10:00` to `20:00` (Start: 600s, End: 1200s)

### 2. Time-Shifting the Output
When the Azure API transcribes Chunk 2, its internal clock starts at `0.0s`. We must shift all the Whisper timestamps back to their global video position.

**The Formula (`_transcribe_chunk_worker`):**
```python
for seg in segments:
    seg["start"] += chunk_start_time  # Global video time
    seg["end"] += chunk_start_time
```
If Whisper heard a word at `5.0s` inside Chunk 2, we mathematically add `600s` to it. The word actually occurred at `605.0s` in the global video.

### 3. Re-Mapping to PySceneDetect (The Intersect)
We now have a massive list of global Whisper segments. We loop through every visual scene generated by PySceneDetect and ask: *"Which Whisper segments fall inside this visual window?"*

**The Formula (`map_segments_to_scenes`):**
```python
for scene in scenes:
    scene_start = scene["start_sec"]
    scene_end = scene["end_sec"]
    scene_text = []

    for seg in all_whisper_segments:
        # Does the Word intersect with the Scene?
        # Condition A: Word starts inside the scene OR Word ends inside the scene
        # Condition B: Word is longer than the scene and completely engulfs it
        if (scene_start <= seg["start"] < scene_end) or \
           (scene_start < seg["end"] <= scene_end) or \
           (seg["start"] <= scene_start and seg["end"] >= scene_end):
            
            scene_text.append(seg["text"])

    # Join all words that fit in this scene
    scene["audio_speech"] = " ".join(scene_text).strip()
```
If a scene spans `00:30` to `00:45`, any word spoken at `00:40` is mathematically appended to that scene.

## Part 2: AST Background Classification

AST works entirely differently than Whisper. Since background noises (sirens, wind) don't have grammatical "sentences" that get cut in half, we can process AST **strictly per-scene**, completely avoiding the complex chunking math.

### 1. Direct Scene Slicing
Instead of making chunks, `ast_parallel.py` slices the raw audio waveform directly at the PySceneDetect boundaries. We use the "Speech-Masked" audio (where voices are muted) to prevent AST from guessing "Speech".

**The Formula (`extract_sounds_optimized`):**
```python
for scene in scenes:
    start_sec = scene["start_sec"]
    end_sec = scene["end_sec"]
    
    # Calculate exact array indices
    start_sample = int(start_sec * sr)
    end_sample = int(end_sec * sr)
    
    # Extract the exact scene from the masked audio array
    scene_audio = audio_masked[start_sample:end_sample]
    
    # Send directly to the AST neural network
    prediction = ast_model.predict(scene_audio)
    scene["audio_natural"] = prediction
```

### 2. Multi-Processing AST
Because AST is highly CPU-intensive (matrix math), iterating through 1,200 small scenes sequentially would take hours. Instead, we use `concurrent.futures.ProcessPoolExecutor`.

1. We gather all 1,200 `scene_audio` numpy arrays into a massive list.
2. We divide the list among **4 separate CPU processes** on the Azure VM.
3. The 4 processes race to classify the scenes simultaneously, returning `[scene_index, prediction]`.
4. We assign the prediction directly back into the master JSON via the `scene_index`.
